BlueSelf Windows 端 UI 优化方案

V2 按你的反馈修订：托盘与目标区彻底去空腔 · 状态不再重复显示 · 图标硬编码已查实 · 目标展示二选一

01需求变更（V1 → V2）

项V1 方案V2 修订
附件托盘有附件时保留托盘框（降对比）任何时候都不要空腔/边框 — 有附件裸排 chip，无附件整体隐藏
发送目标行保留目标行，徽标改圆点去掉整个目标行容器；不显示状态；只留设备名；空态无空腔
状态徽标圆点化保留取消 — 状态左侧列表已可见，不重复
目标展示形态单独一行展示二选一：方案 A 仅左侧列表表达 / 方案 B 保留行但去容器裸排

02查证：目标行手机图标是硬编码

发送目标行（WorkspaceView.xaml）：图标写死 &#xE8EA;（手机）— 硬编码实锤，与设备真实类型无关，连一台 PC 也显示手机图标。
左侧设备列表（DeviceListItem.xaml）：Binding Kind + DeviceKindToGlyphConverter — 正确做法。设备 Kind（"pc"/"tablet"/"phone"，按设备名推导）驱动：pc → \uE968 电脑，tablet → \uE970 平板，其他 → \uE8EA 手机。
修复：方案 B 下目标行改为绑定 SelectedDevice.Kind 复用同一转换器（转换器需提升为共享资源）；方案 A 下整行删除，问题随之消失。

03候选方案：发送目标展示

方案 A · 只在左侧设备栏表达 推荐

  • 删除编辑器顶部的目标行与空态提示条，目标信息完全由左侧承担
  • 左侧列表已有完整表达：选中行品牌色描边高亮 + 状态圆点 + 状态文字
  • 编辑器恢复纯净写作区：上无提示条、下无托盘框，只有文本 + 底部操作行
  • 未选目标点发送：走现有三合一校验，引导方式见待确认项 2
  • En.xaml 的 To: 间距问题随行删除一并消失

优点：去重（状态/目标左侧已有）、编辑区最大化留白、布局最自然。代价：发送时需扫一眼左侧确认目标（选中高亮已足够醒目）。

方案 B · 保留目标行，去容器裸排 备选

  • 目标行继续存在，但无 Border、无底色、无边框，一行小字自然融入编辑区顶部
  • 内容只有：[设备图标(随Kind)] 设备名（品牌色），删状态徽标、删"发送目标："前缀（或极简化）
  • 未选目标：整行不渲染，编辑区顶无任何占位
  • 若保留 "To:" 前缀，按 V1 方案修 En.xaml 间距（Margin 替代尾随空格）

优点：编辑器内有明确的"当前目标"锚点。代价：信息与左侧列表重复。

05待确认

1. 方案 A 还是 B？ 推荐 A：目标/状态信息左侧已完整表达，编辑区去框后最干净。
2.（方案 A）未选目标点发送的引导方式：a 维持日志提示 / b 发送按钮置灰 / c placeholder 动态化为"请先在左侧选择目标设备"——推荐 c，最轻量自然。
3.（方案 B）目标行是否保留 "To:"/"发送目标：" 前缀？ 保留则需同步修 En.xaml 间距；删除则更极简。
